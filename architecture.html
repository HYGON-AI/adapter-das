hcu-sglang-adapter 内部架构图

文字版与协作规约见 docs/architecture.md · 环境变量 docs/env-vars.md · MR 测试 docs/ci.md · 协作入口 CONTRIBUTING.md

设计目标（不变量）：社区版 sglang python 零修改跑海光 HCU ——一切适配经 import 面进入；算子按 triton → vendor → torch 三档路由； 配置裁决 env > hcu_adapter.yaml > 自动探测 > 默认值； 质量收敛在 adapter 层（adapter 全绿 ⇒ 官方 sglang 可用）。

分层总栈（自上而下：调用方向 ↓，接管发生在 import 缝）

应用层 · 上游（不动）
sglang 官方代码python 零修改 · 零 fork
plugin独立仓·性能优化：算子融合/专项内核/新后端，经 seam 接入或直调底层库
vllm（HIP 版）_custom_ops 等被 sglang 复用
import 同名算子库（同名 · 同 ABI · 零调用点改造）· plugin 两条路：经 seam 接入 adapter，或直调 lightop/aiter 等底层库
import 缝 · 接管机制（本仓库）
sitecustomize.pyPYTHONPATH 自动加载 · 顺序化桥编排器
sgl_kernel 同名影子包sglang.kernels 在 HIP 的 AOT 默认路径
hcu_adapter 元路径 hookLibStubFinder：真包优先 + 缺口填空
真包在盘 ⇒ 覆盖加载：extras 只填真包没有的符号 · overrides 强制夺回函数 · post_hooks 加载后 wrap 类方法/判定词 · guards 快关包装。真包不在 ⇒ 惰性桩：import 成功，未实现调用响亮报错。
分流：内核路径 / 其余 import 面
适配层内部（本仓库主体）

sgl_kernel/ op 模块（三档路由）

  • elementwise · layernorm · rope · allreduce
  • moe（gate/align/sum）· gemm_fp8 · gemm_int8
  • flash_attn（fa3 emu）· flash_mla（emu）
  • kvcacheio（transfer_kv_* 16 个，PD/mooncake 调用面）

hcu_adapter/（三分类）

  • 机制层：_base · hcu_env · hcu_config · kill_switch
  • 域桥：prefill_cp · aiter_moe · slimquant · triton_ar · deep_gemm_* · dsa_topk · mqa_logits_emu · hadamard
  • vendor 桩：aiter/（填空）· flashinfer/ flash_attn/（响亮报错）
① triton 首档fp32 累加 · 零主机同步 · graph-safe
② vendor 封装lightop / aiter / flashmla · 压测及格转正
③ torch 兜底import 永不失败 · CPU 可跑
